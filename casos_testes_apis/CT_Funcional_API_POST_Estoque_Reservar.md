# Documentação Técnica de Testes de Integração - API Interna de Gestão de Estoque (Stock-Service)

**Serviço:** Serviço Interno de Gestão de Estoque e Produtos (`Stock-Service`)  
**Endpoint:** `POST /v1/estoque/reservar`  
**Contrato OpenAPI:** [stock-api-openapi.yaml](../stock-api-openapi.yaml)  
**Consumidor Principal:** [CT_Funcional_API_POST_Pedidos.md](./CT_Funcional_API_POST_Pedidos.md) (`POST /pedidos`)  
**Técnicas de Caixa-Preta Aplicadas:** Análise de Valor Limítrofe (AVL) e Particionamento em Classes de Equivalência (PCE).

---

## Premissas de Execução e Oráculos de Teste

1. **Ambientes de Teste:**
   - **`AMB-INT` (Ambiente Integrado):** Instância em execução do microsserviço de Estoque conectada ao seu banco de dados de persistência relacional. Ambiente de teste obrigatório para validação das regras de reserva de estoque, decrements de saldo, transações concorrentes e falhas internas de banco.
2. **Oráculo de Verificação:**
   - **`O-SALDO`:** Verificação direta e atômica da tabela de saldo de armazém no banco de dados de Estoque (campos de saldo físico disponível e saldo bloqueado/reservado temporariamente).
3. **Massa de Dados e Isolamento:**
   - Cada cenário de teste é estritamente isolado. A pré-condição restaura os saldos físicos dos produtos de teste e limpa quaisquer reservas expiradas.
   - `R0` referencia o payload oficial de reserva [`payloads/estoque-reserva-sucesso.json`](../payloads/estoque-reserva-sucesso.json) (`pedidoReferenciaId: "temp-ped-9821"`, `prod-102`, `quantidade: 2`).
