# Documentação Técnica de Testes de Integração - API de Checkout e Pedidos (Market-Rest)

**Serviço:** Serviço de Checkout e Pedidos (`OrderController`)  
**Endpoint:** `POST /pedidos`  
**Contrato OpenAPI:** [openapi.yaml](../openapi.yaml)  
**Microsserviço Integrado:** [CT_Funcional_API_POST_Estoque_Reservar.md](./CT_Funcional_API_POST_Estoque_Reservar.md) (`POST /v1/estoque/reservar`)  
**Técnicas de Caixa-Preta Aplicadas:** Análise de Valor Limítrofe (AVL) e Particionamento em Classes de Equivalência (PCE).

---

## Premissas de Execução e Oráculos de Teste

1. **Ambientes de Teste:**
   - **`AMB-INT` (Ambiente Integrado):** Instância da API de Pedidos conectada ao microsserviço de Estoque ambiente de teste. Ambiente mandatório para validação de regras de negócio, persistência, atomicidade, concorrência e resiliência.
2. **Oráculos de Verificação:**
   - **`O-SALDO`:** Verificação direta do saldo físico disponível e reservado no banco de dados de Estoque.
   - **`O-PED`:** Repositório de persistência do serviço de Pedidos para auditoria do status transacional.
3. **Massa de Dados e Isolamento:**
   - Cada caso de teste é autônomo e isolado. As pré-condições estabelecem o estado do saldo físico do produto e a limpeza de reservas prévias.
   - `P0` referencia o payload oficial válido [`payloads/pedido-sucesso.json`](../payloads/pedido-sucesso.json) (`clienteId: "e2a3c7e4-6a8b-4c2d-98e1-5bc31c38fa22"`, `formaPagamento: "PIX"`, `prod-102`, `quantidade: 2`, `precoUnitario: 49.90`).
   - `TIMEOUT_ESTOQUE` representa o limiar configurado no serviço de Pedidos para aguardar a resposta do Estoque.
