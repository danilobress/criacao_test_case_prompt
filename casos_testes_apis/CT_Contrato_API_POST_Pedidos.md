# Documentação de Testes de Contrato de API - Serviço de Pedidos (Market-Rest)

**Especialidade:** Engenharia de Qualidade de Software / SDET Sênior  
**Tipo de Teste:** Testes de Contrato de API (Validação de Esquemas JSON, Envelopes HTTP e Protocolos)  
**Serviço / Provedor:** Serviço de Checkout e Pedidos (`OrderController`)  
**Endpoint:** `POST /pedidos`  
**Especificação Formal:** [openapi.yaml](../openapi.yaml)

---

## Escopo e Diretrizes de Testes de Contrato

- **Objetivo Estrito:** Validar exclusivamente a "forma do envelope" (tipagem, formatos primitivos, conformidade de schemas JSON Schema, headers HTTP e códigos de status).
- **Isolamento de Negócio:** Ignoram-se regras de saldo de armazém, cálculos de carrinho ou estados internos de banco de dados. Os cenários utilizam o mock server ou provedor para avaliar a integridade dos contratos sintáticos e de protocolo.

| **CT-Contrato-004 - Validação de Negociação de Conteúdo: Content-Type Não Suportado (415)** | Validar a rejeição contratual quando o consumidor envia formato de mídia não suportado pelo endpoint. | - Status HTTP retornado: `415 Unsupported Media Type` (ou `400 Bad Request` com header ProblemDetails).<br>- Rejeição pré-processamento sem consumo de backend. | - Provedor de Pedidos operacional. | **Passo 1 (Enviar Payload em XML)**<br>• **Ação:** Enviar requisição `POST /pedidos` com corpo em XML e header de mídia não suportada.<br>• **Dados de Entrada:** Headers: `Content-Type: application/xml`; Body: `<pedido><clienteId>...</clienteId></pedido>`.<br>• **Resultado Esperado:** Retorno HTTP `415 Unsupported Media Type` ou `400 Bad Request`.<br><br>**Passo 2 (Enviar Payload em Texto Puro)**<br>• **Ação:** Enviar requisição `POST /pedidos` com `Content-Type: text/plain`.<br>• **Dados de Entrada:** Headers: `Content-Type: text/plain`; Body em texto.<br>• **Resultado Esperado:** Rejeição contratual de tipo de conteúdo não aceito. |
